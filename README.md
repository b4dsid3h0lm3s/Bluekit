# Bluekit YRSCR(Your-Ring0-Secure-Check-Rootkit) 
# Bluekit 🔵
> **Your ring0 secure check rootkit.（リング0からセキュリティを検証するルートキット）**  
> `Bluekit`は、`rkhunter`に代表される伝統的なルートキット検知ツールの盲点や限界を評価するために設計された、マルチカーネル対応の概念実証用LKM rootkitです。

## 🎯 プロジェクトの目的
伝統的な検知ツールである`rkhunter`（Rootkit Hunter）は、現代のLinuxサーバーを本当に保護できているでしょうか？それとも、管理者に「偽りの安心感」を与えているだけでしょうか？

従来のルートキット検知ツールは、既知のファイルパスのスキャンや、`sys_call_table`（システムコールテーブル）が直接書き換えられているかどうかのチェックに大きく依存しています。`Bluekit`は、現代のカーネル技術を用いてこれらの古い検知メカニズムに挑戦し、なぜeBPFベースのモニタリングに代表される「次世代のランタイムセキュリティ」が必要不可欠であるかを実証します。

## 🏗️ リポジトリの構造
Linuxカーネル特有の「不安定なABI」による互換性問題（ビルドエラーやクラッシュ）を回避し、コードの可読性を高く保つため、`Bluekit`では特定のカーネルバージョンごとに最適化した個別のソースファイルとMakefileを提供しています。

```text
Bluekit/
├── README.md           # 本ドキュメント（プロジェクト概要と使い方）

└── src/                # カーネルバージョン別のソースディレクトリ
    ├── v5.15/          # Ubuntu 22.04 LTS (Kernel 5.15) 向け
    │   ├── Makefile
    │   └── bluekit.c
    ├── v6.2/           # Ubuntu 22.04 HWE (Kernel 6.2) 向け
    │   ├── Makefile
    │   └── bluekit.c
    └── v6.8/           # Ubuntu 24.04 LTS (Kernel 6.8) 向け
    │   ├── Makefile
    │   └── bluekit.c
```

## 🚀 実証する予定の主要機能

###  LKMのディープな隠蔽（Sysfs & モジュールリスト）
ロードされているカーネルモジュールの連結リスト（`modules`）から自身を削除するだけの手法は、現代では簡単に検知されます。`Bluekit`は、双方向連結リストとSysfsの両方から自身の存在を完全に抹消を試みます。
- `lsmod` コマンドからの隠蔽（カーネルモジュールリストに対する `list_del` の実行）
- `/sys/module/` ディレクトリからの隠蔽（`kobject` のアンリンク）
- **検証ポイント**: `rkhunter`のモジュールスキャンを完全にバイパスし、偽の「OK（検知なし）」が返されるかをテストします。
- **研究用途**でもあるので通常のrootkitと同じような機能を持つことがあります。それらはresearch_dirにまとめてあります、ぜひとも視点を広げてみてください。

## 📖 検証手順 (Step-by-Step)

### 事前準備
**注意: 以下のテストは、必ず使い捨てが可能な仮想マシン（VM）環境でのみ実行してください。**
**注意: 実システムチェック用にも欲しい場合。Issuesへ書いてください**

```bash
# ビルドツールと、現在実行中のカーネルに一致するヘッダーファイルをインストールします
sudo apt update
sudo apt install build-essential linux-headers-\$(uname -r)
```

### 検証の流れ

1. **リポジトリのクローン**
   ```bash
   git clone https://github.com
   cd Bluekit
   ```

2. **ベースラインスキャンの実行（ロード前）**
   モジュールを読み込む前のクリーンな状態で `rkhunter` を実行し、現在のシステムの安全性を確認します。
   ```bash
   sudo rkhunter --check
   ```

3. **Bluekitのビルドとロード**
   現在実行中のカーネルバージョン（`uname -r` で確認可能）に一致するディレクトリへ移動します。
   ```bash
   # 例：Kernel 5.15 環境の場合
   cd src/v5.15/
   make
   sudo insmod bluekit.ko
   ```

4. **監査スキャンの実行（ロード後）**
   `Bluekit`がロードされた状態で再度 `rkhunter` を実行し、ツールが隠蔽されたルートキットを検知できるか検証します。
   ```bash
   sudo rkhunter --check
   ```

5. **クリーンアップ**
   検証が終わったら、必ずモジュールをアンロードしてビルドファイルを削除してください。
   ```bash
   sudo rmmod bluekit
   make clean
   ```
